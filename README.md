# 🏙 Аренда в Таиланде — PropertyHub Telegram Bot

Telegram polling-бот с UI-first карточками, поиском по неофициальному GraphQL PropertyHub, SQLite и эвристическими подборками. **Не использует Playwright, Selenium, AI или ключи к сторонним сервисам.**

## Старт (Windows PowerShell)

Требуется Python 3.11+.

```powershell
cd C:\Users\egori\ph-bot
py -3 -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
py -3 main.py
```

В `.env` нужны ровно две строки:

```env
TG_BOT_TOKEN=123456789:YOUR_TOKEN
ADMIN_ID=123456789
```

`ADMIN_ID` — **числовой Telegram user ID** администратора, не имя пользователя.

Linux/macOS: `python3 -m pip install -r requirements.txt && cp .env.example .env && python3 main.py`.

Файл БД создаётся автоматически в `data/propertyhub.sqlite3`. Один запущенный экземпляр polling-бота на один токен. Начальный фонд объявлений собирается в фоне при старте.

## Пользовательский интерфейс

`/start` открывает одну обновляемую панель: 3 строки × 2 колонки плюс доступная админу широкая кнопка «Админка».

- **Новые** — до 100 новых объявлений в соответствии с персональными настройками. Сначала отправляется мгновенное сообщение «Поиск по фильтрам выполняется…», затем после первой HTTP-страницы появляется первая карточка, пока другие страницы загружаются параллельно с просмотром.
- **Поиск и фильтры** — независимый профиль. Цена, площадь, тип комнаты, сортировка (новые/обновлённые/дешёвые), все найденные GraphQL-поля `amenities` (32 шт.) и `facilities` (20 шт.) с множественным выбором; дополнительный фильтр района/города/названия ЖК по тексту, а также ручные ID зоны (`zoneIds`) и ЖК (`projectId`). Кнопка «Копировать в другой раздел» синхронизирует профили.
- **Подборки** — за 1 / 7 / 30 дней, по адаптированной детерминированной оценке (0–100), основанной на сравнениях цены и бат/м² с аналогами *в локальной выборке*, новизне, площади, полноте данных, наличии фото и контактов. В карточке показывается оценка.
- **Рынок** — средняя аренда по районам и ЖК по сохранённой выборке, `n` объявлений, RUB по официальному курсу ЦБ РФ (когда доступен).
- **Избранное** и **Скрыть** — раздельно и постоянно в SQLite для каждого пользователя.
- **Подробнее** — цена/депозит/предоплата, оборудование, контакты, текст объявления и все URL фотографий, показанные в галерее Telegram при поддержке их CDN. При нажатии «Назад» дополнительные сообщения и альбомы удаляются.
- **Админка** — пользовательская статистика, последние посещения, число объявлений и взаимодействий, ручное обновление индекса, отключение фонового обновления, режим обслуживания, состояние курса ЦБ РФ и ошибки API.

Бот подтверждает callback-кнопки мгновенно; запросы к PropertyHub выполняются в отдельных `asyncio` задачах. Для UX исходное меню остаётся, карточки редактируются при перелистывании; при необходимости удаляются и пересоздаются в случае ошибок Telegram CDN. Ввод цен и других значений идёт сообщением с последующим удалением ввода и подсказки. Никакие ключи, кроме токена Telegram, не нужны.

## Что подтверждено и что ограничено

- Используется `POST https://api.propertyhub.in.th/graphql` с операцией `zoneListings` и persisted-query SHA-256, **извлечёнными из Network браузера в октябре 2026**. Подтверждённые в пользовательском тестировании переменные: `price`, `roomInformation`, `amenities`, `facilities`, `order`, `page` и `perPage`. GraphQL API **не публично документирован** и его формат может измениться.
- Детальная карточка получает `__NEXT_DATA__` с `https://propertyhub.in.th/en/listings/{slug}---{id}`. Если страница блокирует запрос, показываются базовые поля из GraphQL без выдуманных сведений.
- **«100 новых» означает до 100 новых из первых 3 страниц GraphQL выдачи** (до 5 при локальном текстовом геофильтре), не полное сканирование десятков тысяч объявлений. У PropertyHub есть промо-размещения, поэтому дополнительно сортируем считанную выборку по `createdAt`. При малом числе совпадений результат может быть меньше 100.
- Текстовый фильтр «Район / город» накладывается **локально на названия/адреса** уже полученной выборки, поэтому может пропускать более дальние страницы. Для серверной точной фильтрации используйте ID зоны из GraphQL (`zoneIds`). ID зон автоматически не открываются.
- **Подборки/Рынок — статистика локально накопленного индекса**, не репрезентативная полная статистика Таиланда. Поскольку `zoneListings` не возвращает все `amenities` и `facilities` в строке выдачи, подборки используют структурные параметры; персональные флаги удобств из настроек не переоцениваются в подборках.
- `contactInformation.isAgency` иногда противоречит свободному тексту продавца — не считаем это гарантией «от собственника».
- Для полной галереи Telegram может выдавать ошибку загрузки внешних фото; тогда бот отправит URL фотографий. Для массового production-использования проверьте условия PropertyHub и получите разрешение на автоматизированный доступ; в проекте предусмотрены паузы и ограничение запросов.
- Бот не оценивает реальные условия доступности квартиры: объявление может уже быть сдано.

## Архитектура

```
main.py ─ aiogram 3 polling
  phbot/bot.py        Telegram UI, inline callbacks, background tasks
  phbot/propertyhub.py    GraphQL client / детальные HTML страницы
  phbot/filters.py    Параметры, whitelist, сопоставление зон
  phbot/render.py     Тексты/клавиатуры/HTML escaping
  phbot/db.py         aiosqlite WAL + профили/объявления/флаги
  phbot/ranking.py    Локальная относительная value score
  phbot/fx.py         XML ЦБ РФ THB/RUB (опционально)
  phbot/config.py     .env
```

## Тесты

```bash
python -m unittest discover -s tests -v
python -m compileall -q .
```

Юнит-тесты проверяют структуру GraphQL-запроса, формирование фильтров, расчет оценок и парсинг структуры. **Живой end-to-end тест Telegram и PropertyHub здесь не проводился**: он требует реального токена и сетевого доступа к API.

## Оценка подборок

Адаптация из [nofumex/viet-aggregator](https://github.com/nofumex/viet-aggregator) (`internal/ranking/ranking.go`): относительная аренда и цена/м² к медиане аналогичных квартир (район + тип), свежесть, площадь, полнота и доверие. Для отсутствующих сопоставимых данных нейтральная оценка без фиктивного дисконта. На карточках пользователь видит оценки, а не утверждения об инвестиционной выгоде.
