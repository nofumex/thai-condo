# Thai Condo — Telegram-бот аренды в Таиланде

Поиск квартир на PropertyHub через GraphQL, полные карточки через Next.js JSON, SQLite и aiogram 3.

> **Статус:** используется **неофициальное API** PropertyHub, оно может меняться без уведомления. Результат поиска и цены — предложения из объявлений, не гарантированная доступность объектов. Перед публикацией/массовым использованием проверьте условия доступа к сайту и лимиты.

## Быстрый запуск

Python 3.11+:

```powershell
cd C:\Users\egori\ph-bot
py -3 -m pip install -r requirements.txt
Copy-Item .env.example .env  # только если .env ещё нет
notepad .env

```

`.env`:

## Логика разделов

- **Поиск и фильтры** — временный независимый профиль с произвольными параметрами.
- **Настройки** — постоянный профиль для **«Новые» и «Подборки»**. Сброс делает профиль полностью пустым, не накладывая скрытых ограничений по цене/району.
- **Новые** — GraphQL-поиск по текущим настройкам с **постраничной догрузкой**. Нет искусственного ограничения в 100 карточек. При редких локальных фильтрах, включая депозит ≤ 1 месяца, бот автоматически проверяет до **48 страниц за проход**, прежде чем предложить продолжить. Это **не полная проверка** всех ~150 тысяч объявлений Бангкока. Во время поиска показывается число проверенных страниц; пользователь может уйти в меню и отменить задачу. Общее число от PropertyHub приблизительно для локальных фильтров.
- **Подборки** — свежие результаты PropertyHub по текущим постоянным настройкам + ограничение по возрасту. Бот **сначала** сканирует до **80 страниц** и формирует единый пул кандидатов, **затем** рассчитывает сравнительные показатели и показывает **до 100 лучших** объявлений в зафиксированном порядке. Позиции при перелистывании не пересортировываются; при новом запуске собирается и оценивается новый пул. Это выборка из первых 80 страниц, **не лучшие 100 среди всех предложений PropertyHub**. Во время сбора показывается прогресс.
- **Избранное** — сохранённые объявления; оценка пересчитывается при каждом просмотре, поэтому новизна постепенно ухудшается.
- **Рынок** — все определённые для пяти городов районы с редакционными оценками по 10-балльной шкале. Средние цены, если есть, считаются только по локальной выборке.

## Фильтры

Цена, площадь, тип квартиры, город, несколько районов города, ID зоны/ЖК, название/адрес, депозит максимум в месячных платежах, даты публикации (включительно), сортировка, оснащение квартиры и инфраструктура ЖК. Важные ограничения:

- Города используют **Next.js JSON** городских страниц PropertyHub, из которого запрашиваются `zoneIds`, и передают ID в GraphQL `listingAttributes.zoneIds`. Фильтр координат перепроверяет выдачу. Если PropertyHub не возвращает ID города, бот показывает ошибку вместо выдачи чужого города. Это API не задокументировано и нуждается в живом E2E-тесте на соответствующей версии сайта.
- Районы и депозит проверяются локально по объявлениям, полученным из серверного поиска. Редкие совпадения требуют сотен/тысяч просмотренных записей; после проверки лимита страниц появляется возможность продолжить, но бот не обещает полноту всей базы.
- В API встречаются объявления, у которых числовое поле ошибочно содержит `3000000000`, превышающее диапазон GraphQL `Int`. При такой **конкретной ошибке сериализации** сбойная страница дробится на 20/10/5/1 объявлений, и пропускаются только невосстановимые единичные записи. Ошибки авторизации, сети и другие GraphQL-ошибки не маскируются. При 60 объявлениях на странице 12 это сохраняет исправные записи, вместо полной остановки поиска.
- Поля цены в запросах ограничены допустимым диапазоном 32-битного GraphQL Int; интерфейс отклоняет ввод цены больше `2 147 483 647`. Неправильные `NaN`/`Infinity` не отправляются в API.
- Максимум депозита исключает объявления, где его размер **не указан**. Сведения о депозите находятся в `priceLandAndHouse.forRent.deposit`; формат — `AMOUNT` (баты) или `MONTH` (месяцы).
- Фильтр по датам относится к `createdAt`, а не `refreshedAt`.
- Бассейн и тренажёрный зал отправляются как `facilities.pool/fitness`, даже если они были выбраны в старом разделе amenities.

## Карточки и подробности

Поиск сразу возвращает: главное фото, заголовок, ЖК, цену, площадь, этаж, спальни/ванные, депозит и предоплату (если указаны), автора и контакты (если есть), создано, верификацию, координаты. Координаты сопоставляются с приблизительными зонами районов. Никакие поля с `null` не показываются как достоверные сведения.

«Подробнее» получает `/_next/data/{buildId}/en/listings/{slug}---{id}.json` вместо HTML, которое возвращало 403. Выводятся галерея, оснащение, описание и контакты. Подробности кешируются на 24 часа, текст и альбомы удаляются при «Назад». При недоступности JSON открывается внешняя ссылка и показывается явная ошибка, а не поддельные «полные» данные.

Идентификатор Next.js сборки может меняться после релизов сайта. Бот пытается обнаружить новый ID из HTML, если это возможно; если HTML заблокирован, необходимо обновить `PROPERTYHUB_BUILD_ID` вручную. Автоматическое определение в этом случае не гарантируется.

## Рейтинг 0–100

Сумма весов: цена 15, цена/м² 18, площадь 10, этаж 8, спальни 7, депозит 13, свежесть 11, район 11, верификация 7. Без достаточных сопоставимых вариантов используются нейтральные ориентиры, а доверие к оценке снижается. Свежесть — `11 × exp(−возраст_в_днях/21)`, поэтому оценка снижается с каждым днём даже для объектов в избранном.

**Рейтинг не является измерением объективного качества жилья**. Дорогое кондо в хорошем районе может проиграть доступному в менее популярном; личные предпочтения могут требовать других весов. Районы — приблизительные кластеры, не официальные полигоны; см. [методологию и источники](docs/areas.md).

## Архитектура

- `phbot/propertyhub.py` — GraphQL, Next.js JSON, получение ID зон
- `phbot/filters.py` — независимые профили, local/server фильтрация
- `phbot/geography.py` — геокластеры и редакционные оценки районов
- `phbot/ranking.py` — прозрачная временная оценка
- `phbot/bot.py` — aiogram, страницы, меню, альбомы
- `phbot/render.py` — Telegram HTML/клавиатуры
- `phbot/db.py` — SQLite WAL, профиль, избранное, кеш
- `phbot/fx.py` — необязательный официальный THB/RUB от ЦБ РФ

## Проверка

```powershell
python -m unittest discover -s tests -v
python -m compileall -q phbot
python -m scripts.smoke_live  # необязательная проверка PropertyHub, включая проблемную страницу 12
```

Автоматические тесты проверяют структуру HTTP-запросов с `httpx.MockTransport`, фильтрацию, даты, депозит, географию, динамику рейтинга, HTML/клавиатуры, восстановление повреждённой страницы с 59/60 объявлениями, независимую загрузку 13-й страницы, автопоиск депозита за 8-й страницей и неизменность порядка готовых подборок. **Реальный E2E с Telegram и живым PropertyHub не был выполнен в этой среде**. Если сервис блокирует Next.js JSON (403), отдельная живая проверка выводит WARNING, а не скрывает проблему или ошибочно утверждает, что GraphQL-поиск не работает. После применения обновления выполните живой smoke-тест, проверьте поиск Пхукета и Паттайи, галерею, возврат из пустой выдачи и сброс постоянных настроек.

## Проверка HTTP 403

В новой версии запросы Next.js выполняются через отдельный HTTP-клиент с минимальными заголовками (без `Origin` и `Referer`). В октябре 2026 именно такой запрос ранее возвращал 200 из PowerShell, а первоначальные запросы HTML возвращали 403. Это не гарантирует доступность endpoint в будущем.

```powershell
python -m scripts.check_next_json
```

Команда сравнивает HTTP-статус минимального и бывшего браузероподобного набора заголовков на **одном URL**. `403` может быть блокировкой по IP или иным ограничением; не следует автоматически считать его сменой `buildId`.
